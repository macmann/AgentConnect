# Tools and MCP — Phase 3 development slice

Workspace administrators register approved read-only tools in **Tools**. Builders can test and attach enabled tools, but cannot change destinations, credentials or public-access policies. Operators can inspect traces. Viewers have no tool capability. Tool and connector changes are audited, tenant-scoped and guarded by optimistic revisions.

## Configure and try

1. Set exact approved HTTP hostnames in `TOOL_ALLOWED_HOSTS` (for example `api.search.brave.com`). HTTPS is required. Private development endpoints need an explicit `host:port` in `TOOL_PRIVATE_HOSTS`. These settings are empty by default and independent of model/website settings. Cloud destinations also need permitted environment egress. Restart the API after changes.
2. Store credentials in workspace **Secrets**, then register a tool in **Tools**. The tool configuration stores secret IDs, never credential values. A workspace administrator must acknowledge that the integration is read-only and its output is appropriate for the workspace.
3. Use **Test**, supply JSON matching the displayed argument schema, and inspect the returned result and recent traces.
4. In an agent's configuration, attach the tool and set the maximum calls per response. Save the draft and start a new playground conversation.
5. The runtime asks the configured model for a strict JSON plan, validates all calls against the attachment list and schemas, executes them sequentially, then streams an answer using the results as untrusted reference data. Planning is an additional provider request; reported usage includes both planning and final generation. Tool results cannot install tools or alter policy.
6. Inspect expandable tool results in chat, saved conversation history, or **Tools**. Trace records include tool revision, sanitized arguments/result, status, duration, run reference and error code.

Tool definitions and connector configuration use current workspace settings, including existing conversations and published agents. Publication pins attachment IDs and call budgets, not integration endpoints or tool revisions. Disable/archive or revoke public access to prevent subsequent execution. Public deployments require explicit public access on every attached tool. That policy is checked again before planning and each call. Anonymous users receive tool outputs only after that opt-in; no workspace trace-list endpoint is public.

## Supported adapters

- **HTTP:** a fixed URL, GET only, explicitly allowed string query parameters, no authentication, bearer or an `X-*` API-key header backed by a secret. URLs cannot contain credentials, query strings or fragments in registry configuration. The transport checks approved destinations and private IPs, pins DNS for direct connections, preserves cloud proxy/TLS trust and refuses redirects. Requests have no automatic retries.
- **PostgreSQL:** credential is a PostgreSQL connection URL without URL options. Approve its exact hostname and port using `TOOL_DATABASE_HOSTS`. Use a dedicated login granted SELECT only on the configured tables/views; superuser and BYPASSRLS roles are rejected. The registry fixes schema, table/view, returned columns, allowed equality filters and at most 100 rows. Models supply filter values, never SQL. Queries use validated quoted identifiers and driver parameters inside a read-only transaction with statement/lock deadlines. Production connections require verified TLS; external cloud database access also requires supported TCP/network access. MySQL/SQL Server, schema discovery and arbitrary/generated SQL are not implemented.
- **Web search:** provider-neutral adapter interface with an initial Brave Search implementation. Store a Brave API key, approve `api.search.brave.com`, and register a search tool. Strict safe search and bounded results are enforced. API configuration supports exact allow/deny result domains; the initial UI uses five results and unrestricted result domains. Links are returned as data and are never fetched automatically. Recency and additional search providers remain future extensions.
- **MCP:** official TypeScript SDK with Streamable HTTP, fixed approved URL and optional secret-backed bearer authentication. Discovery caches bounded tools/resources/prompts plus server capability metadata. Registration selects a discovered tool whose `readOnlyHint` is true, and requires administrator acknowledgement. Before executing, the client verifies the current tool schema and read-only hint against the registered schema. Schema drift fails explicitly and requires rediscovery plus tool editing to approve the changed schema. A disabled connector prevents attached tools from running. Resources/prompts are listed for inspection; they are not automatically read or inserted into agent context.

MCP supports finite POST responses in JSON or SSE and best-effort bounded session termination with DELETE on the same approved endpoint. Background GET subscriptions, OAuth discovery/login, legacy SSE/stdio transports, notifications, resumable sessions and automatic server-directed endpoint changes are not supported. MCP metadata is untrusted: `readOnlyHint` does not prove a remote server has no side effects. Integrate only reviewed servers and restrict the remote credential's permissions. Disabling and re-enabling a connector clears its discovery cache; refresh before registering/editing tools.

## Limits and safety boundaries

An agent can attach at most eight tools and perform at most five sequential calls per response. Registry deadlines are 0.5–15 seconds, request bodies/results are bounded, HTTP responses are limited to 256 KiB and each persisted/grounding result to 16 KiB. Invalid plans, unknown tools, schema violations, redirects, timeout, changed MCP capabilities and revoked policies fail explicitly. No malformed-plan fallback executes a tool. Interrupted traces are recovered after five minutes, alongside agent-run recovery.

JSON schemas are bounded by depth/node/byte limits and cannot use references, regex patterns or formats. This intentionally rejects some complex MCP tools. Cancellation closes transports/database connections; a remote server may already have received a read request. Credential strings and sensitive JSON property names are redacted, but tool results can contain business/personal data; workspace administrators must select appropriate outputs. Trace retention and advanced redaction controls remain future work.

This slice is intentionally read-only. HTTP mutations, unrestricted SQL, generated code, approval/resume flows, OAuth connectors, tool templates, recursive/native function-calling loops, automatic retry/circuit breakers and advanced parallel orchestration remain unimplemented. HTTP GET and MCP read-only declarations rely on the reviewed upstream service honoring its contract; they are not a remote side-effect sandbox. Use minimally privileged credentials. Tool selection uses a separate JSON planning call across the existing provider adapters; it is not a claim of provider-native tool-call protocol support.

Hosted search, live third-party MCP services, live model tool selection and production database access need organization credentials and permitted egress. Local fixture validation does not establish that acceptance or enterprise production readiness.

Agent Configure → Tools supports Automatic, Always and Disabled usage policies plus usage instructions. Automatic may choose no tools; Always requires at least one relevant valid call within the call budget; Disabled retains attachments without planning or execution. Agent prompt instructions and tool usage instructions are provided to the planner. See [usage policy details](agent-runtime.md#tool-and-knowledge-usage-policies).
