# Quality lab (Phase 8 initial release)

Run `pnpm db:migrate` to apply migration 0010, then restart the API, web and worker. No new environment variables are required. Open **Quality** in a workspace.

1. Create a named dataset. Paste a JSON array of examples, each containing `input` and `expectedBehavior`. Deterministic evaluation requires at least one of `expectedAnswer`, `contains`, `forbidden`, or `expectedSourceIds` per example. Optional `tags` and string `metadata` help classify failures. IDs are generated when omitted; editing preserves IDs when retained in JSON. Copy the displayed examples to export, or paste them to import. Datasets support optimistic revision checks and archival with retained run history.
2. Optionally import assistant message IDs from existing workspace conversations. The paired user prompt and latest reviewed correction are used; without a correction, the original answer is used. Imported answers must be reviewed for correctness. Importing never implies that an answer is trustworthy.
3. Save the agent draft in Agents, choose it in Quality, and run the dataset. Standard agents reuse the provider, retrieval, citation and approved read-only tool runtime. Runs do not create chat conversations, fire deployment webhooks, or publish changes. Tool calls can still contact configured external services.
4. Review outputs, scores, provider failures, latency, reported token usage, retrieval recall and cost. Configure registered model rates in Operations to estimate cost; missing rates or usage produce an unknown cost, never zero. Rates are snapshotted at queue time. Judge cost is included when both models report usage and have rates.
5. Optionally choose a registered judge model. Strict JSON scores cover correctness, relevance, groundedness and policy compliance; the score is their average, capped by any deterministic checks. Malformed judge output fails the case. Untrusted examples and retrieved content are passed as data; model judges still require human review.
6. Compare against a completed baseline for the same agent, dataset revision and evaluator. The summary reports changes in pass rate, average latency and known estimated cost. Changed datasets or evaluator settings require a new baseline.
7. Workspace administrators can enable an agent publication gate for a dataset, evaluator and required pass rate. Publication requires a completed evaluation of the exact saved draft and current dependency fingerprint. Any failed case blocks gated publication. Builders may evaluate and publish passing drafts but cannot disable the administrator's policy. Disabling or changing a gate is audited. Existing deployments remain pinned to their published versions.

Exact answers and required/forbidden terms compare normalized case and whitespace. Retrieval recall is the fraction of expected source IDs retrieved, and a partial recall fails that check. Each example passes at score >= 0.8 by default; the API supports a configurable minimum score and optional end-to-end case latency ceiling. A run's pass rate includes every example. Case-level errors are persisted as safe codes; provider messages, keys and prompts are not written to terminal logs by the evaluation worker.

Workers claim jobs with leases, heartbeat during execution, checkpoint completed cases, resume incomplete cases after a crash and stop reclaiming after three attempts. Cancellation prevents completion and further cases; an active provider call is interrupted by the next heartbeat (up to ten seconds) or its 90-second case deadline. A crash can repeat an uncheckpointed provider/tool call and incur another charge. Requester permissions are checked at execution and before each case.

Dependency fingerprints conservatively cover all workspace model revisions, knowledge/source revisions and readiness, embeddings, tool/connector revisions and encrypted credential state. Unrelated workspace changes can therefore require a new evaluation. The fingerprint contains no plaintext credentials. Publication takes row locks on existing dependency records; this is a point-in-time quality check, not a guarantee that external providers or content will remain unchanged after publication.

## Initial release limits

Datasets contain at most 100 examples; each prompt is at most 12,000 characters. One worker processes one evaluation at a time. History shows the latest 100 runs. Evaluation records and results are tenant-scoped and durable, but large-history pagination, retention policies and dataset immutable revision browsing remain extensions.

Structured generative agents and workflow evaluation are explicitly rejected or unavailable. Human/custom evaluators, semantic retrieval ranking benchmarks, tool-selection ground truth, provider reproducibility controls, regression thresholds, workflow publication gates, scheduled evaluations and automatic knowledge-gap recommendations remain follow-up work. Tags, expected source IDs and failed outputs support manual gap review today. No live provider accuracy or production scale claim is made by protocol-fixture tests.
