# Yoma Bank RFP — core AI capability assessment

Assessment date: 2026-10-11. Repository: AgentConnect, branch `feat/release-monitoring`, commit `4774814`.

## Scope and conclusion

Reviewed both supplied documents: **Yoma AI Assistant RFP Final September 2026** (functional requirements, analytics and demo scenarios) and **Yoma Bank AI Assistant RFP Version 2, October 2026** (technical requirements). Both contribute requirements; the October document does not explicitly withdraw the September functionality.

Excluded: mobile SDKs, enterprise identity/security/compliance certifications, residency, encryption/KMS, SIEM integration, commercial proposals and contractual availability/DR obligations. Included: grounding and hallucination control, safe AI action capability, model/runtime optimization and measurable response performance because these directly affect AI behavior.

**Conclusion:** AgentConnect has a substantial PoC foundation: document RAG, independent knowledge administration, streaming chat, visual workflows, versioned agents, conversation review/evaluations and a mature AI-to-human-to-AI support journey. It is **not yet fully compliant with the core AI requirements**. Major gaps are Myanmar-language acceptance, approved/versioned knowledge releases, banking-specific grounded fallback/clarification and escalation, channel-consistent quick actions, the specified analytics/CSAT, dynamic model routing and token optimization.

This is a source review, not a new live-provider or bank-data acceptance test. Existing validation largely uses explicit protocol fixtures. A configurable language/model field is not evidence of language accuracy, and a displayed citation is not proof of factual entailment.

Statuses: **Implemented** = concrete code/UI path exists; **Partial** = narrower behavior or incomplete requirement; **Missing** = no supported implementation found; **Unverified** = needs bank/provider/workload acceptance rather than only more UI.

## Recommended delivery priorities

1. **Bank PoC configuration and multilingual acceptance.** Obtain approved bank documents and answer rubrics. Build English, formal Myanmar and mixed-language datasets across the six mandatory scenarios, out-of-scope questions, ambiguity and escalation. Compare available live models; bank reviewers approve answers. Include Myanmar handoff triggers and real concurrent-staff tests. Do not set an arbitrary accuracy commitment before agreeing the rubric.
2. **Approved knowledge and strict grounded behavior.** Add draft/review/approved knowledge releases, provenance/version browsing and rollback; optionally pin a deployment to a knowledge release. Define greeting exceptions, clarification, approved-source-only answers and customer-friendly no-answer/handoff behavior. Evaluate claim faithfulness, table retrieval and scanned-document requirements; add reranking/query rewriting only where measured results justify them.
3. **Customer experience parity.** Add quick actions with separate label/message, populate-or-send behavior, support for the eight listed enquiries, equivalent widget/hosted rendering and explicit customer-care action. Add shared logo/colors/name/welcome branding and durable customer-session continuity where required.
4. **RFP analytics and continuous improvement.** Agree outcome/user/utilization definitions; add actual AI resolution outcomes, customer CSAT, category aggregation, failed-search/gap views, daily trends, arbitrary date ranges and Excel export. Keep operator reviews separate from customer satisfaction.
5. **October runtime optimization and control.** Add tokenizer-aware component budgets and payload preview, summarization, user quotas, evaluated light/heavy-model routing and provider failover. Benchmark TTFT/end-to-end latency before and after changes. Define bank gateway/external RAG integration boundaries.
6. **Messaging channels if still required for the selected rollout.** Implement Messenger; Viber is optional. Treat each as a real inbound/outbound customer channel, not a knowledge connector.

Transactional banking actions need a separately agreed scope. Most September support scenarios can be demonstrated through approved guidance and human escalation without enabling financial mutations.

## Implementation follow-up: priorities 1–4

The `feat/bank-core-ai` implementation adds reviewed immutable knowledge releases and rollback/pins, approved-knowledge-only answer/clarify/no-answer handling, eight editable channel-consistent banking quick actions, and four configurable support journeys with existing consent-based handoff. See [configuration and limits](bank-core-ai.md). The assessment above records the earlier repository baseline rather than bank acceptance of these additions. Myanmar-language validation, live-bank correctness, provider performance and the other roadmap priorities remain outside this implementation.
