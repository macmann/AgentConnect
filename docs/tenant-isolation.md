# Tenant isolation regression checks

Run `pnpm test:security` against isolated local test infrastructure. The suite refuses production mode. Stop the normal API/worker development processes first; the tests create their own API instance and explicitly process a queued connector job. A separate worker could claim their fixture jobs. Start normal development processes again afterwards.

The fixture creates three workspaces across two organizations: two sibling workspaces and one unrelated organization. Each initial administrator has only a workspace membership. Resources are created through the real API, generated artifacts and knowledge text use the real private object store, and model output uses an explicit protocol fixture. Provider credentials are fixture-only values; no live provider accounts or outbound provider requests are needed. Cleanup removes only the uniquely generated fixture organizations, storage keys and HNSW indexes.

## Corrected boundary

Widget chat and handoff already enforced the originating site and current widget policy. The generative message-access helper checked only the conversation bearer token and active deployment, allowing a widget token to mint an artifact grant without an originating-site match. It now loads the conversation channel/origin and applies the same widget allowlist and origin binding to guest artifact grants and actions. Workspace-authorized historical review and hosted conversation access retain their existing contracts. No migration or credential change is required; restart the API after updating.

## Scope and remaining work

These are executable regressions for documented API boundaries, not an independent penetration test or proof covering every endpoint, race or database query. Resource routes can return 403 for an existing inaccessible object and 404 for an unavailable object; the suite checks denied content/state rather than claiming uniform existence concealment. The dedicated test rate-limit addresses are unique to each run; application rate limiting remains enabled.

Signed artifact paths remain short-lived bearer capabilities, valid for up to five minutes after issuance. A previously issued valid link can be used until expiry; blocking a new grant does not revoke that existing link. Treat links as private and do not log/share them. Immediate signed-link revocation would require a separate capability/version design.

Checks cover new requests and queued connector authorization. They do not establish cancellation of an already-authorized streaming response on membership change. RLS, comprehensive retention, external identity lifecycle, parser isolation, source ACL mirroring, broad concurrency/race assessment and independent security review remain separate hardening work. No production infrastructure or other tenants' real data are modified by this suite.
